Delivered behavior
==================
- Compatible complete downloads make a one-second bounded fresh-position read when the journal is clean, then open local audio. Progress/ownership writes do not gate availability; a missed deadline falls back to the durable local cursor.
  Local playback journals its position and reconciles when the server returns.
  Known conflicts retain both histories; intentional rewinds never use max(position).
- Concurrent synchronization callers await shared work; forced selected-book work
  can drain a newer checkpoint. Errors/backoff are per book; old account completion
  cannot release a newer account's synchronization gate.
- Ambiguous playback-start retries reuse the original request ID and revision.
  The backend's accepted-ID path is tested to avoid a second ownership claim.
- Startup failures identify stage/category without titles, accounts, grants or URLs.
- Truncated files are not considered downloaded. Old transfer callbacks cannot
  update a replacement transfer. Removing a playing local copy first attempts a
  server handoff; the file is kept if the handoff fails. Pausing allows removal.
- Books, Authors and Series navigation; author series are fetched independently
  of the first page of books. Numbered series use provider sequence ordering and
  retain fractional/unknown numbers. Author and series IDs remain structured.
- One-tap Continue listening, list/grid layouts, publication-year
  sorting, recently-added/author/title/duration sort, Not started filter,
  explicit complete/downloading/paused download badges.
- Dates retain provider precision. The installed provider only supports global
  publication-year ordering; exact dates are shown in book details when supplied.
  No unsupported exact-date sort is offered. Unknown dates stay unknown. Existing downloads and API consumers accept optional new metadata.

Follow-up product work and risks
===============================
- Verify ordinary online device handoff and the exact removal -> streaming ->
  re-download scenario on real devices, including an offline device reconnecting
  after a second device listened. Competing offline histories still need a choice.
- A full listening history/undo system needs a durable retention/migration design.
  Add smart rewind and per-book speed with explicit behavior tests, then collections
  and opt-in next-in-series playback. Preserve existing sleep/bookmark behavior.
- Exact-day ordering needs a separate bounded metadata index; the installed
  provider getOrder implementation does not support publishedDate.
  Provider publishedDate may be absent or refer to publication rather than the
  audio edition's release. Do not label unknown dates as known audiobook release
  dates. Provider sequence metadata, not invented title parsing, determines order.
- Provider filter data and scoped author inventory are bounded by the existing
  8-MiB transport limit. Very large author inventories may need a paginated index.
- A same-size damaged local file can pass the size check and then fail decoding.
  Full media validation and automatic repair require additional tests.
- This iteration targets the native iPhone/iPad audiobook experience. Existing web
  clients remain compatible; matching new web navigation is separate product work.

Additional Nov 27 continuity and listening UX corrections
- Clean downloaded copies consult newer server progress briefly; dirty local
  history still requires conflict-safe reconciliation. A late cancelled read
  cannot begin playback. Known access denial stops local playback.
- Unchanged paused heartbeats no longer manufacture dirty history. Initial
  intents, rewinds, play/pause and finished changes still produce checkpoints.
- Chapter rows visibly distinguish Playing from Current chapter / Paused, support
  direct chapter playback from details, and retain the native seek fences.
- Mark as unread uses the existing conflict-aware offline-progress protocol to
  reset canonical position/finished state without taking playback ownership,
  starting audio, deleting downloads or erasing bookmarks. Dirty history is
  discarded only after acknowledgement; failed resets preserve it.
- Listen begins playback at the synchronized cursor, then automatically downloads
  in the background after actual audio advances. Completed local parts can serve
  later chapter/part transitions; the current stream is never interrupted just
  to switch its source. Visible download progress/check/paused indicators and
  Pause/Resume controls remain. A device setting disables automatic downloads.
  User-paused partial downloads remain paused. Cellular use is disclosed there.

Combined iPad qualification exposed a paused-clock race: periodic callbacks
could move the cursor or report playing again after Pause, creating a redundant
write that conflicted with another device. Pause now captures the current item
clock once. Later notices cannot move a paused checkpoint, and active notices
sample the current item rather than accepting a timestamp queued before a seek.
The regression injects stale zero/90-second notices around a real seek and Pause,
then verifies an unchanged paused seek makes no server writes or conflict.
Known chapter-end and finished-book coordinates remain canonical; a sleep-boundary
pause does not replace that exact endpoint with a resetting AVPlayer clock.
Play/Pause labels now follow playback intent, including buffering. Failed opens
stop that intent so one Play tap retries, and a stale cancelled local fallback
cannot pause a newer selection. The activation-failure regression retains this
single-tap retry contract; chapter rows distinguish starting from a user pause.
