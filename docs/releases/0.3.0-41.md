# Arrify 0.3.0 (41) — beta testing

- Home and saved songs quietly retry brief network and server failures before
  offering a retry action. Existing Home content remains visible during recovery.
- Reconnect automatically when a usable network returns, with bounded retries
  while the app is active. Offline launches preserve the signed-in session.
- An unavailable local server address falls back to the verified public address.
  Interrupted token refreshes keep their durable recovery identifier across routes.
- Home pull-to-refresh also refreshes saved songs. The full-screen player offers
  a working Retry button instead of suggesting an unavailable pull gesture.
- Avoid cancelling the first Home request when the network monitor starts.
- Recover transient preparation failures quietly, without replaying Next. Cache
  downloads can retry through the verified alternate address after a route failure.
- Clear the previous cover when a new song title arrives while its artwork loads.

Please test Wi-Fi/cellular changes, VPN interruptions, offline launch and reconnect,
Home pull-to-refresh, and saved-song recovery from the full-screen player on iPhone
and iPad. A successful load has no added retry delay. With no reachable server,
server content needs connectivity; loaded content is retained in memory. This
update does not add persistent offline library browsing or change cache capacity,
retention, or download selection.

Session expiration, revocation, refresh replay protection, and fast cached song
transitions remain supported. Intended for internal and existing external TestFlight
beta testers. No App Store release.
